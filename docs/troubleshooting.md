# 困ったときの対処

画面に対象と次の操作が表示されている場合は、その案内から確認してください。記録できたか分からないときは、同じ操作を繰り返す前に結果を確認します。サーバーの設定変更が必要な場合は、設置先のサーバー管理者へ依頼してください。

## パスキーを使えない

「対応ブラウザ」の案内が出る場合は、iPhoneではSafari、AndroidではChromeアプリを直接起動し、登録時と同じHTTPSのURLをアドレス欄へ貼り付けます。LINEなどのアプリ内ブラウザからは開き直してください。証明書の警告が出る場合は、無視せずサーバー管理者へ連絡します。

端末の画面ロック、指紋・顔認証などが利用可能か確認してください。認証をキャンセルした場合は画面から再試行できます。登録済みのパスキーを使えない場合は、[復旧コードによる復旧](usage.md#パスキーを使えなくなった場合)へ進みます。

サイトのドメインを変更した場合、以前のパスキーをそのまま使えないことがあります。原因が分からないまま、初期登録やDBの作り直しは行わないでください。

## QR受付を開いても読み取れない

管理者としてログインすることと、受付端末の登録は別です。[受付端末の登録](usage.md#qr受付に使う端末を登録する)で、申請・管理者の承認・申請したブラウザでの利用開始まで終えてください。

同じスマホでも、ブラウザや公開URLが異なると受付用の登録を使えません。通常のブラウザで同じURLを開き、端末の登録状態と有効期限を確認します。Cookieやサイトの登録情報を消した場合、受付用の登録も失われることがあります。期限切れ・失効の場合は管理者に確認し、新しく申請してください。

## カメラを許可できない・QRを認識しない

1. ブラウザのサイト設定でカメラを許可します。端末側でブラウザへのカメラ許可も必要な場合があります。
2. ほかのアプリがカメラを使用していないか確認し、「カメラを起動」を押し直します。
3. QR全体が枠に入り、暗すぎたり反射したりしない位置に調整します。スマホに表示するQRは、画面の明るさも確認します。

氏名の入力で代わりに受付する機能はありません。使えないまま受付を続けず、管理者へ連絡してください。管理者が記録を手動で追加する場合は、[履歴の操作](usage.md#記録を手動で追加訂正取り消す)で本人確認と理由を残します。

## 受付結果が分からない・通信が切れた

「この受付の結果を確認」を押し、対象と結果を確認します。未完了で「同じ内容を再送」が表示された場合だけ、そのボタンで再送できます。新しくQRを読み取って別の受付要求を作らないでください。

再読込後はQR自体を保持していないため、同じ内容を再送できない場合があります。結果の照会で確認できなければ、管理者が「入退室履歴」で記録を調べてから受付を再開します。通信がない状態では、入室・退室の完了を確定できません。

## 「すでに入室中」「入室記録がない」と表示される

受付画面の入室・退室モードと対象者を確認します。モードは自動では切り替わりません。退室忘れなどで記録が実際の状態と異なる場合は、管理者が履歴を確認し、理由を残して訂正します。日付が変わるだけでは自動退室しません。

## 記録や名前の変更を保存できない

同じ対象をほかの操作で更新した場合、古い内容での上書きを止めます。入力内容を控えて、対象の最新状態を読み直してください。通信失敗の場合は、完了表示が出る前に保存できたと判断せず、最新の一覧や履歴を確認します。理由や入力値に誤りがある場合は、画面の案内に従って直してください。

## 削除が処理待ち・保留のまま

個人情報の削除は、別サーバーへ最新の削除指示を保管してから実行します。画面で指示を受け付けた時点では削除完了ではありません。処理番号と表示されている案内をサーバー管理者へ伝えてください。

サーバー管理者は外部保管先の接続・容量・権限と保守処理を確認し、[削除の再試行](operations.md#削除が保留になった場合)を行います。DBや削除台帳の処理済み欄を直接書き換えないでください。

## サーバーの起動や更新が止まった

以降はサーバー管理者向けです。停止した段階と表示された記録先を控え、同じ配布物・設定・コマンドで再検査します。既存のDB・volume・秘密ファイル・復号鍵を削除してやり直さないでください。

| 案内・症状 | 確認すること |
| --- | --- |
| ポートが使用中 | このシステム専用の内部ポートと、既存HTTPSサーバーの接続先が一致しているか。既存サイトの80・443番を奪わないこと |
| 秘密ファイルを読めない | ホスト側の所有者・権限と、必要なサービスへの読取専用の受渡し。全員に読める権限へ広げないこと |
| 容量不足 | アプリと外部保管先それぞれの空き容量。他サービスのデータを無断で消さないこと |
| 移行・更新を拒否 | 配布物の版・指紋と、対応する既存DB世代。移行台帳を編集して回避しないこと |
| HTTPSの警告・接続不可 | DNS、証明書の対象ホストと期限、既存HTTPS設定。設定検査に成功してから変更を反映すること |

診断は[導入](install.md)、再開とバックアップ・復元は[運用](operations.md)の手順を確認してください。サービスの停止を伴う操作は、施設の管理者へ受付停止を知らせてから行います。

## 問い合わせる前に

画面下部の版、確認日時、端末・OS・ブラウザ、操作の順序、期待した結果、実際の案内を控えてください。通常の不具合は[GitHub Issues](https://github.com/mameoffice/mame-inout/issues)へ報告できます。

画像やログを添える場合は、氏名・メールアドレス・QR・設定コード・招待コード・復旧コード・Cookie・秘密鍵・DB資格情報を除いてください。生のログ全体や設定ファイル全体の公開は避けます。脆弱性や漏洩の可能性を含む内容は、公開Issueへ書かず、[セキュリティに関する案内](../SECURITY.md)を参照してください。

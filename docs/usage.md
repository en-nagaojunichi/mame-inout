# 入退出管理システムの使い方

現在は開発中です。管理者・利用者・受付端末の管理、QR発行とカメラ受付、在室一覧・履歴・訂正・CSV・表示設定を実装しています。新機能は検証中のため、登録する情報は動作確認用にしてください。実際に使う端末とブラウザでの確認も必要です。

## 管理者の画面と、QR受付に使う端末

**管理画面**は、管理者が自分のスマートフォンやPCでパスキーを使ってログインし、利用者の登録、QR発行、管理者の追加、受付端末の承認などを行う画面です。ログイン後は「管理ホーム」を表示します。PCでは左のメニュー、スマホでは上部の「メニュー」から移動できます。

**QR受付に使う端末**は、入口などに置き、利用者のQRコードを読み取って入退出を記録するスマートフォン・タブレットです。受付用に承認されたブラウザで使い、日常のQR読み取りでは管理者のログインやパスキー認証は不要です。受付用の資格で名簿や管理者の設定は操作できません。

登録の流れは「受付に使う端末で申請 → 管理者が『QR受付端末』で承認 → 申請した端末で利用開始」です。受付に使う端末にも、管理者と同じサイトを開いてください。共有の受付端末へ、管理者個人のパスキーを登録する必要はありません。

## 最初の管理者を登録する

1. AndroidではChrome、iPhoneではSafariを起動し、サーバー管理者から案内されたHTTPSのURLをアドレス欄へ貼り付けて開きます。証明書の警告が出ないことを確認してください。
2. 「最初の管理者を登録」が表示されたら、サーバー管理者から受け取った設定コード、表示名、メールアドレスを入力します。設定コードの有効期限は発行から15分です。
3. 「パスキーを登録」を押し、端末の指紋・顔認証・画面ロックなどの案内に従います。
4. 登録後に表示される復旧コードを、端末とは別の安全な場所へ保存します。コードはこの画面で一度だけ表示されます。
5. 「保存したので閉じる」を押し、「管理ホーム」が表示されていることを確認します。

パスキーは管理者が個人で使う端末に登録してください。共有の受付スマートフォンに管理者のパスキーを追加する運用は避けてください。

メールアドレスは管理者を識別するために使います。確認メールは送信されず、画面にも「未確認」と表示されます。本番で使うURLを確定してから登録してください。ドメインが変わると、同じパスキーをそのまま使えない場合があります。

復旧コードの発行だけに失敗した場合は、パスキーの再登録は不要です。「管理ホームへ」から進み、「自分の設定」で復旧コードを発行してください。

## ログインとログアウト

登録したときと同じURLを開き、「パスキーでログイン」を押します。登録済みのパスキーを選び、端末の案内に従ってください。「管理ホーム」が表示されたらログイン完了です。

操作を終えるときは「ログアウト」を押し、ログイン画面に戻ったことを確認します。30分間操作しなかった場合、またはログインから12時間が経過した場合も、再度ログインが必要です。

パスキーの変更、管理者の招待・停止、復旧コードの発行、受付端末の承認・失効では、対象と影響を確認して実行します。ログインなどでパスキーの本人確認をしてから5分以内は、その確認を利用します。時間が過ぎている場合は「本人確認して承認」などのボタンから再確認します。認証をキャンセルした場合、その変更は行われません。

## パスキーを追加・変更・失効する

管理メニューの「自分の設定」を開きます。「パスキー」には名前、登録日、最終利用が表示されます。

- **追加する**：「パスキーを追加」から名前を入力し、本人確認の後、新しく使うパスキーを登録します。
- **名前を変更する**：対象の「名前を変更」を押します。端末や保存先を見分けられる名前にしてください。
- **使えなくする**：対象の「失効」を押し、対象と影響を確認します。そのパスキーでログインしたセッションも使えなくなります。

紛失したパスキーを失効するときは、先に別のパスキーでログインできることを確認してください。最後のパスキーは失効できません。

## 別の管理者を招待する

1. 管理メニューの「管理者」を開き、「管理者を招待」を押して、招待する本人の表示名とメールアドレスを入力します。
2. パスキーで本人確認した後、表示された招待コードを控えます。コードは一度だけ表示され、15分間有効です。
3. サイトのURLと招待コードを、招待した本人だけに安全な方法で伝えます。コードをURLの末尾に付けたり、公開の掲示板へ載せたりしないでください。
4. 招待された方は、自分の端末でサイトを開き、「招待された管理者の登録」からコードを入力してパスキーを登録します。別の管理者でログイン中の場合は、先にログアウトしてください。
5. 登録後に表示される復旧コードを保存します。

招待コードは登録が完了すると再利用できません。管理者の停止は、設定画面の対象者にある「管理者を停止」から行います。停止した管理者は、使用中のログイン状態を含めて使えなくなります。最後の有効な管理者は停止できません。

## 管理者の名前を変更する

1. 管理者としてログインし、管理メニューの「管理者」を開きます。
2. 「管理者」の一覧で、対象者の「名前を変更」を押します。自分の名前も変更できます。
3. モーダルに表示された現在の名前を書き換え、「保存」を押します。名前は1〜100文字で入力してください。

表示名だけを変更します。メールアドレス、権限、パスキー、ログイン状態はそのままです。名前だけの変更に追加のパスキー認証はありません。キャンセルした場合は変更せず、通信に失敗した場合は入力した名前を保持して案内します。

## 復旧コードを保管・再発行する

復旧コードは、パスキーを使えなくなったときに本人のログインを復旧するためのものです。初回登録・招待からの登録・復旧後に表示されたコードは、安全な場所に保存してください。各コードは1回だけ使えます。

「自分の設定」の「復旧コードを発行」または「復旧コードを再発行」から、新しいコードを発行できます。再発行すると、それまでの復旧コードはすべて使えなくなります。閉じた後に同じコードを再表示することはできません。保存し忘れた場合は、再発行して新しいコードを保存します。

## パスキーを使えなくなった場合

1. ログイン画面の「パスキーを使えない場合」を開きます。ログイン中の場合は、先にログアウトしてください。
2. 登録済みのメールアドレスと、未使用の復旧コードを1つ入力します。
3. 新しく使うパスキーを登録します。復旧の開始から5分以内に登録を完了してください。
4. 新しい復旧コードを保存し、設定画面を開けることを確認します。

復旧コードは、復旧を開始した時点で使用済みになります。パスキー登録をキャンセルした場合も、同じ画面を開いたまま、開始から5分以内であれば、進行中の登録手続きから再試行できます。画面の再読込、別のコードでの開始、有効期限切れの後は、別の未使用コードでやり直してください。復旧を完了するまでは、以前のパスキーとログイン状態が保持されます。復旧中の許可だけで管理操作はできません。

新しいパスキーの登録が完了すると、以前のパスキー、すべてのログイン状態、以前の復旧コードは無効になります。新しく登録したパスキーと、保存した新しい復旧コードを使用してください。

復旧コードもすべて失った場合は、次のサーバー管理者向けの手順で復旧します。

## サーバー管理者が復旧コードを発行する

この操作は、設置先のサーバーを管理する方が対話端末で行います。対象の管理者本人を確認してから実行してください。

Composeファイルのあるディレクトリで、次を実行します。`admin@example.test`は登録済みの管理者メールアドレスに置き換えてください。実際の起動に追加のComposeファイルを使っている場合は、同じ組合せを指定します。

```sh
docker compose exec api node dist/admin-recovery-code.js admin@example.test /tmp/new-recovery-code
```

コードはAPIコンテナ内の指定ファイルへ保存されます。既存ファイルは上書きされません。同じ保存先が残っている場合は、別の新しいファイル名を指定してください。非対話実行では発行できません。

ファイルの内容は、第三者に見えず、出力を記録しない手元の対話端末で確認します。公開ログ、チャット、画面共有へコードを載せないでください。コードは対象の管理者本人へ安全に渡し、前の節の復旧画面で使用します。復旧が完了したら、保存したコードのファイルを削除してください。

発行すると、その管理者の以前の復旧コードと、進行中の復旧は無効になります。以前のパスキーとログイン状態は、新しいパスキーで復旧が完了するまで保持されます。

## QR受付に使う端末を登録する

管理者用のログインと受付端末の登録は別です。管理者がログインしただけでは受付端末になりません。

1. 受付で実際に使うスマートフォンのブラウザで、管理者と同じサイトの「QR受付に使う端末を登録」を開きます。管理者のログインは不要です。
2. 見分けやすい端末名を入力し、「管理者へ承認を申請」を押します。
3. 表示された端末名と8桁の確認コードを管理者に見せます。申請の期限は10分です。
4. 管理者は自分の端末で管理メニューの「QR受付端末」を開き、一覧を更新します。対象端末の「承認」を押し、実際の受付に使う端末と確認コードが一致することを確認します。
5. 有効期間を1〜90日で指定して承認します。初期値は30日です。直近の本人確認から5分を過ぎている場合は、パスキーで再確認します。
6. 受付端末側の「承認の状態を確認」を押します。承認済みになったら、「このブラウザで利用を開始」を押します。
7. 「このブラウザで登録済みです」と有効期限が表示されていることを確認し、「QR受付を開く」へ進みます。

資格を受け取れるのは申請したブラウザだけです。確認コードを別のブラウザに入力して登録することはできません。申請から10分を過ぎる前に、承認と「このブラウザで利用を開始」まで完了してください。登録後は、申請の10分が過ぎても管理者が指定した有効期限まで使えます。

受付端末を紛失した場合は、管理者の設定画面で対象端末を失効してください。過去の記録は保持され、その端末は次の受付操作から拒否されます。期限切れ、拒否、失効、ブラウザの登録情報を消した場合は、管理者に確認して新しく申請します。

## QR受付に使う端末の名前を変更する

管理メニューの「QR受付端末」を開き、対象にある「名前を変更」を押します。現在の端末名を書き換え、モーダルの「保存」を押してください。名前は1〜100文字で入力します。

端末名だけの変更なので、再申請や再承認は不要です。登録・承認状態、有効期限、過去の入退出記録は保持します。申請中や停止した端末も名前を変更できますが、名前を変えても利用可能な状態にはなりません。受付画面の名前は、状態の再確認や再読み込みで更新されます。

## 利用者を登録・検索・編集する

管理メニューの「利用者」を開き、「利用者を登録」から表示名を入力します。ふりがな・所属・利用者コードは任意です。同姓同名でも登録できます。利用者コードを設定する場合は、この施設内で重複しない値にしてください。メールアドレスや電話番号などの登録は不要です。

名前・ふりがな・所属・コードで検索し、状態で絞り込めます。結果が続く場合は「続きを表示」で確認してください。対象の「編集」から情報を変更できます。別の操作で更新されていた場合は上書きせず案内するので、一覧を更新してからやり直します。

「利用停止」では、その方のQRも失効します。在室中の場合は停止できません。記録を管理者が確認し、必要な退室補正や取消を先に行う必要があります。訂正の操作画面は準備中です。「利用再開」を行っても、以前のQRは使えません。再開後に新しく発行してください。

## 個人QRを発行・保存・印刷する

1. 「利用者」で対象の「QRコード」を押します。新規登録の直後は「登録した方のQRを発行」からも進めます。
2. 対象者と影響を確認し、「発行」または「再発行」を押します。本人確認の期限を過ぎている場合は、パスキーで再確認します。
3. 表示されたQRを「QR画像を保存」で保存するか、「印刷」で紙に印刷します。
4. 保存・印刷を終えてから「保存したので閉じる」を押します。

閉じた後に同じQRを再表示することはできません。再印刷や保存し忘れた場合は再発行してください。再発行すると、以前に配ったQRはすぐに使えなくなります。在室状態と過去の記録は保持します。「現在のQRを失効」では新しいQRを作らず、現在のQRを使えなくします。

QRを持っている人は、そのQRで受付できます。本人以外へ渡したり、公開のチャットやSNSへ載せたりしないでください。コピー・貸し借りによる代理利用を完全に防ぐものではありません。

発行の応答を確認できなかった場合は、すぐに繰り返さず最新の状態を確認してください。画像を失った場合は再発行が必要になり、以前のQRは無効になります。

## カメラで入室・退室を受け付ける

1. 承認済みの同じブラウザで「QR受付を開く」へ進みます。
2. 「入室」または「退室」を選び、現在の受付モードを確認します。モードは自動では切り替わりません。
3. 「カメラを起動」を押し、ブラウザのカメラ許可を有効にします。背面カメラを優先して起動します。
4. 利用者の紙、またはスマホ画面のQRをかざします。成功時は「入室を記録しました」または「退室を記録しました」と、対象者・施設の時刻が表示されます。
5. 結果の表示が消えたら、次の方のQRをかざします。同じQRを続けて読むときは、いったんカメラから外してください。

映像はブラウザ内で解析し、サーバーへ送りません。読み取ったURLを勝手に開くこともありません。カメラを利用できない場合は管理者に確認してください。氏名だけで受付する代替操作はありません。ページを離れたり画面を非表示にするとカメラを停止します。

通信が切れた場合は、完了を確認するまで新しいQRを読まないでください。「この受付の結果を確認」から、同じ受付の結果を照会します。未完了で画面の案内に「同じ内容を再送」が出る場合だけ、そのボタンから再送します。新しい受付要求を作って繰り返す操作ではありません。

再読込するとQR自体は失われます。途中の要求IDだけをこのタブに保持して結果を再確認できますが、再読込後に同じ内容を自動で再送することはありません。記録の有無が分からない場合は管理者に確認し、確認してから受付を再開してください。通信が戻る前に完了表示するオフライン受付には対応していません。

## 在室状況を確認する

管理ホームには「記録上の在室者」と「退室忘れなどの要確認」の人数、最近の入退室を表示します。各人数から在室一覧へ進めます。在室一覧は名前・所属や「要確認の人だけ」で絞り込めます。

「要確認」は、入室から12時間以上経過した記録、または施設の日付を跨いだ記録です。日を跨いでも自動では退室しません。QRの未読取や退室忘れによって、実際の滞在と異なる場合があります。

管理ホームと在室一覧は30秒ごとに更新します。「取得日時」は最後に情報を取得できた時刻です。通信に失敗した場合は前回の情報と案内を表示するため、接続を戻して「最新の情報に更新」を押してください。

## 履歴を検索する

管理メニューの「入退室履歴」を開き、開始日・終了日、名前・所属、状態を指定して「検索」を押します。期間は画面に表示された施設の時刻での**入室日**を対象にします。前日に入室して当日に退室した記録を探す場合は、開始日に前日を含めてください。

「詳しい条件」では所属だけの絞り込み、QR受付／手動追加、訂正の有無を選べます。通常の検索は取消済みを含みません。取消した記録は状態を「取消済み」に切り替えて検索してください。「前のページ」「次のページ」で移動できます。

在室一覧や管理ホームから特定の人の履歴を開いた場合は、その人だけに絞り込まれます。「利用者の絞り込みを解除」で全員の検索へ戻せます。

## 記録を手動で追加・訂正・取り消す

手動操作には変更理由と、直近5分以内のパスキーによる本人確認が必要です。画面に本人確認の案内が出た場合は「パスキーで本人確認」を押してください。

- **追加する**：「手動で記録を追加」から対象の利用者を検索・選択し、施設の時刻で入室日時と変更理由を入力します。退室済みなら退室日時も入力します。未退室は空欄にして「記録を追加」を押します。
- **訂正する**：対象の「詳細・訂正」から「時刻を訂正」を選び、日時と変更理由を入力して「訂正を保存」を押します。
- **取り消す**：「詳細・訂正」から「記録を取り消す」を選び、対象と影響を確認して理由を入力します。「この記録を取り消す」を押すと在室状況と通常の集計から除外されます。

未来の日時、入退室の逆転、他の在室区間との重複は保存できません。別の操作で更新された場合は上書きを止めるので、入力内容を確認してから最新の記録を読み直してください。夏時間の切り替えで日時を一つに確定できない場合も、入力内容の確認が必要です。

変更前後・実行者・理由は「変更履歴」で確認できます。取消済みの記録は変更できません。新しい記録が必要な場合は、理由を付けて手動で追加してください。

保存結果が分からない場合は成功と表示しません。モーダルを閉じて最新の履歴を確認し、同じ記録を重ねて追加しないようにしてください。

## CSVを保存する

履歴で検索条件を確定してから「CSVをダウンロード」を押します。確認モーダルの条件を確認し、必要な本人確認を済ませてダウンロードしてください。フォームを入力しただけでは検索条件は変わらないため、条件を変更した場合は先に「検索」を押します。

CSVは全ページを対象とし、上限は10,000件です。上限を超えた場合は期間や利用者で絞り込んでください。利用者コード・名前・所属・入退室時刻・状態・訂正有無・タイムゾーンなどを、見出し付きのUTF-8 BOM形式で出力します。数式として解釈され得る文字列には先頭に文字列用の記号を付けます。

CSVには個人情報が含まれます。保存先と共有先を確認し、不要になったファイルは施設の方針に従って削除してください。

## 名前・アイコン・ファビコンを変更する

管理メニューの「表示設定」を開きます。既定の名前は「入退出管理システム」です。

1. 表示名を入力します。1〜64文字で設定できます。
2. システムアイコンと、ブラウザのタブに表示するファビコンのPNG画像を選びます。画像は4MB以下を選択し、画面の案内に従ってください。256×256ピクセル以内へ縮小し、保存する画像はそれぞれ64KB以下にします。
3. プレビューで確認し、「変更を保存」を押します。ほかの端末には画面を開き直すと反映されます。

「すべて既定に戻す」や画像ごとの「既定に戻す」はプレビューを戻す操作です。確認後に「変更を保存」で反映してください。通信失敗時は入力が残ります。他の管理者が先に変更した場合は、必要な内容を控えてから「現在の設定を読み直す」で確認します。

名前や画像を変更しても、登録済みのパスキー・受付端末・QR・記録は保持されます。OSのパスキー管理画面に保存された名前は、自動で変更されるとは限りません。

### 導入担当者向け：画像の保存が413エラーになる場合

手前のWebサーバーでリクエスト容量を制限している場合は、このシステム用の設定を192KB以上にしてください。Nginxの設定例は [nginx.conf.example](../infra/nginx.conf.example) を参照してください。

## 操作を完了できないとき

- **「対応ブラウザ」の案内が出る**：AndroidはChrome、iPhoneはSafariのアプリを直接起動し、同じURLをアドレス欄へ貼り付けてください。LINEなどのアプリ内でページを表示している場合も、この手順で開き直します。
- **設定コード・招待コードが使えない**：入力内容と有効期限を確認してください。初期設定済みの設定コードや、登録済みの招待コードは使えません。
- **端末の認証をキャンセルした**：操作は完了していません。画面からもう一度試してください。復旧の登録中は、同じ画面を開いたまま、開始から5分以内であれば、その登録手続きから再試行できます。画面の再読込、別のコードによる開始、期限切れの後は、別の未使用の復旧コードを使ってください。
- **通信が途切れた・結果が分からない**：「状態を再確認」や「登録の状態を再確認」で確認します。受付端末の資格受取で応答が失われた場合は、申請した同じブラウザから、申請期限内にもう一度利用開始を試せます。
- **招待・復旧の登録結果が分からない**：画面で登録済みと確認できた場合は、設定画面を開いて復旧コードの発行状態を確認してください。パスキーの再登録は不要です。確認できない場合は、同じ画面の有効な登録手続きから再試行するか、ログイン画面で新しいパスキーを選んで確認してください。
- **復旧コードの発行結果が分からない**：再表示はできません。パスキーでログインできる場合は設定画面で再発行し、新しいコードを保存してください。
- **「操作が続いています」と表示される**：繰り返し押さず、画面で案内された時間を待ってから試してください。
